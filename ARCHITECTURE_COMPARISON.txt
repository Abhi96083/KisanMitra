### Why CORS Blocks It?
```
Browser security model:
  1. Web pages can only access resources from SAME ORIGIN
  2. Origin = Protocol + Host + Port
  3. localhost:5000 ≠ 10.126.227.21:80 = DIFFERENT ORIGINS
  4. Browser blocks the request before sending it
  5. "Failed to fetch" error
```

### Why This Works?
```
Key Points:
  1. Browser → Flask (same origin) = ✅ ALLOWED

  3. CORS policy doesn't apply to server-to-server
  4. Flask can freely communicate with any IP
  5. Flask returns data to browser (same origin)
  6. No security violation = ✅ WORKS!
```

## WHY CORS EXISTS

```
Browser CORS Policy Protects Against:

❌ Malicious Scripts:
   - Web page from attacker.com
   - Tries to steal data from bank.com
   - Browser blocks (different origin)

❌ Data Exfiltration:
   - JavaScript from hacker site
   - Fetches user data from trusted service
   - Browser blocks (protection!)

❌ Unauthorized Actions:
   - Script from evil.com
   - Transfers money on bank.com
   - Browser blocks (security!)

✅ Our Use Case (SAFE):
   - Localhost page (trusted)
   - Using Flask proxy (controlled)
   - Reaching ESP32 (local network)
   - No external threats
   - Solution: Use proxy instead of direct request
```

---

## WHY SERVER-TO-SERVER IS SAFE

```
CORS Policy Only Applies To:
  ❌ Browser-to-Server requests
  ❌ JavaScript from one origin accessing another

CORS Policy Does NOT Apply To:
  ✅ Server-to-Server requests
  ✅ Backend API calls (Flask to ESP32)
  ✅ No browser security policy involved

Why?
  - Server-to-Server is controlled by developers
  - No untrusted scripts involved
  - Network is isolated (not the internet)
  - Server can use firewalls, authentication
  - No browser security policy needed

Therefore:
  - Flask can freely request 10.126.227.21
  - No CORS headers needed
  - Direct communication allowed
  - Perfect for our proxy solution!
```
